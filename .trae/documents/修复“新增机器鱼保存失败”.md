## 问题概览

* 现象：在“新增机器鱼”点击保存后报错“保存失败”。

* 前端在 `src/renderer/src/views/fish/index.vue` 的 `save()` 中只在发生异常时通用提示，未显示具体原因；主进程会打印 `'Error creating fish:'` 日志。

## 可能原因与证据

* 名称校验：`name` 为空或长度 > 20 会直接阻止保存（`src/renderer/src/views/fish/index.vue:350-356`）。

* 轨迹校验：任一轨迹行的 `alt` 与 `depth` 必须“二选一”，否则阻止保存（`src/renderer/src/views/fish/index.vue:327-346, 358-363`）。用户若新增轨迹行但未填写，会导致一直失败。

* 后端字段映射不完整：服务层保存时未覆盖 UI 中的 `upCommand/downCommand/surfCommand/navigateCommand/lightOnCommand/lightOffCommand/wifiCommand`，虽不致崩溃，但数据可能丢失（`src/main/database/index.ts:431-484`）。

* 运行时错误信息未透出：当前仅在渲染层 `console.error('保存失败:', error)`，用户界面看不到具体消息（`src/renderer/src/views/fish/index.vue:451-454`）。

* 数据库连接或路径异常：数据库指向 `file:./src/main/prisma/dev.db`（`.env`），如权限或路径异常会在主进程报错（`src/main/app.ts:20-24`）。

## 修复方案

1. 前端错误提示优化

   * 在保存失败时，显示主进程返回的 `error.message` 具体原因。

   * 对轨迹校验：允许空行（两者皆空）通过；仅当有值时要求互斥，避免“新增就失败”的体验。
2. 字段映射补全

   * 在服务层 `fishService.create/update` 中补充 UI 字段：`upCommand/downCommand/surfCommand/navigateCommand/lightOnCommand/lightOffCommand/wifiCommand` 的持久化，保证编辑/新增一致。

   * 对 `preload/index.ts` 和 `index.d.ts` 中的类型保持与服务层一致（当前 `index.d.ts`已包含完整字段，`preload/index.ts`的参数注释可同步）。
3. 运行时可观测性

   * 在主进程 `ipcMain.handle('fish:create')` 的 catch 中返回结构化错误（保留 console），前端据此展示详细信息。
4. 验证

   * 手动测试：

     * 名称 ≤ 20 且非空；不添加轨迹或添加但仅填写 `alt` 或 `depth`；保存成功。

     * 添加无效轨迹（两者都填）确认前端能给出明确提示。

     * 验证命令字段保存后在“编辑”中能正确回显。

   * 如需自动化，补充一个最小集成测试脚本（调用 `window.api.fish.create/findAll/delete`）。

## 交付内容

* 前端：改进轨迹校验逻辑与错误消息展示。

* 后端：服务层字段映射补全；IPC 返回结构化错误。

* 文档：在 README 或注释中说明轨迹填写规则与失败提示。
