### 正则解析问题确认

您非常敏锐地发现了问题！

**问题现象**：
*   当消息为 `...,ack, ...` (ack前无空格) 时，解析正常。
*   当消息为 `..., ack, ...` (ack前有空格) 时，前端不弹窗。

**原因分析**：
在 `src/main/protocol/ProtocolParser.ts` 中，声通协议的正则表达式是：
```typescript
private static ACOUSTIC_REGEX = /\+\+\+AT:(\d+):RECVIM,\s*(\d+),(\d+),(\d+),ack,(.*)/i
```
这个正则在匹配 `ack` 时，**没有允许 ack 前面有空格**。
*   `\s*(\d+)`：允许数字前有空格。
*   `,ack`：**强制要求逗号后紧跟 ack**。

当收到的消息是 `..., 299049` (逗号后有空格) 时，`ack` 部分前面的匹配其实没问题（因为前面的数字匹配允许空格）。
**但是**，让我们看完整的消息结构：
`+++AT:54:RECVIM, 14,2,1, ack, ...`
正则中：`RECVIM,\s*(\d+),(\d+),(\d+),ack,(.*)`
*   `\s*(\d+)`: 匹配 ` 14` (Group 2)
*   `,(\d+)`: 匹配 `,2` (Group 3)
*   `,(\d+)`: 匹配 `,1` (Group 4)
*   `,ack`: 匹配 `,ack`

如果消息是 `...,1, ack,...` (1后面逗号后有空格)，那么正则 `,ack` 就会匹配失败，因为正则期望逗号后紧跟 `a`，但实际是空格。

### 修复计划

修改 `ACOUSTIC_REGEX`，在 `ack` 的逗号前后都允许空格：
```typescript
// 原正则
/\+\+\+AT:(\d+):RECVIM,\s*(\d+),(\d+),(\d+),ack,(.*)/i

// 修正后的正则
/\+\+\+AT:(\d+):RECVIM,\s*(\d+),\s*(\d+),\s*(\d+),\s*ack,(.*)/i
```
我将把所有的逗号分隔符后都加上 `\s*`，以增强对不同格式（带空格/不带空格）的兼容性。
