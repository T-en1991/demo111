### 关于消息解析逻辑的分析与解释

感谢您的详细说明，这帮我理清了关键的 ID 定义：
1.  **`ID=01`** (Payload 中的 ID): 这是**鱼的 ID (fishCode)**，对应数据库中的 `fishCode` 字段，也是鱼的业务唯一标识。
2.  **`srcId` / `destId`** (AT指令头中的数字): 例如 `RECVIM` 后的 `2,1`。
    *   **2 (srcId)**: 发送方，即**鱼的声通 ID (acousticId)**。
    *   **1 (destId)**: 接收方，通常是上位机/浮标。
    *   这个理解对于解释 `NAVIGATE-SUCCESS` 等回执至关重要。

### 当前逻辑中的问题

在 `src/main/protocol/ProtocolParser.ts` (L29) 中：
```typescript
const dest = atMatch[4] // 1 (通常是鱼?)
// ...
return { type: 'NAV_SUCCESS', raw: data, srcId: dest }
```
代码目前错误地将 `atMatch[4]` (即协议中的 destId, 值为 1) 当作了 `srcId` 返回。
而在您的描述中：`+++AT:57:RECVIM, 16,2,1...` 中的 **2** 才是鱼的声通 ID。
根据正则 `RECVIM,\s*(\d+),(\d+),(\d+)`：
*   Group 2: 数据长度 (16)
*   Group 3: srcId (2) -> **这才是鱼的 acousticId**
*   Group 4: destId (1)

**当前代码取的是 Group 4 (destId)**，所以它错误地认为 ID 是 1。这是导致逻辑混乱的根源。
